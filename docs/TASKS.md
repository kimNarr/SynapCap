# SynapCap 작업 목록

갱신일: 2026-11-09. 현재 코드와 확인된 제보를 기준으로 관리한다.

목표: 사용량을 신뢰할 수 있고, 조회 실패 원인을 이해하고 복구할 수 있는 위젯으로 완성한다.

## 운영 기준

- 상태: `접수` → `수정 중` → `검증 대기` → `배포 대기` → `배포 완료`. 자료·환경이 부족하면 `확인 필요`로 남긴다.
- P1: 잘못된 사용량 표시, 주요 조회 기능 실패 등 우선 해결할 문제. P2: 복구 경험·유지보수 개선.
- 실제 앱 종료·데이터 손상 등 심각한 문제가 확인되면 긴급 대상으로 승격하고 수정·검증 후 배포를 권유한다.
- 일반 수정은 누적한 뒤 아래 배포 조건을 충족했을 때 배포를 권유한다. 태스크 작성이나 완료만으로 자동 배포하지 않는다.
- 각 태스크에는 변경 커밋, 검증 환경·결과, 남은 제약, 배포 버전을 기록한다. 구현과 실제 검증을 구분한다.
- 기존 사용자 변경을 보존한다. 로고 시안 생성은 범위에서 제외한다.

## SC-001 — 오류 원인과 복구 동작 통일

현재 펼침 상세에는 로그인·시간 초과 구분이 있지만 탭에서는 대부분 `조회 오류`로 합쳐진다. 문자열에 포함된 단어만으로 오류를 판단하는 부분도 있다.

- [x] 미설치, 로그인 필요·만료, 시간 초과, 조회 제한, 서버 오류, 응답 형식 변경, 한도 없음의 상태를 명시적으로 정의한다 (`StatusKind`).
- [x] 탭·링 상세·막대·트레이·진단 화면이 동일한 상태를 사용하도록 공통 분류를 마련한다. 한도 없음은 트레이 숫자 집계에서도 제외한다(SC-011).
- [x] 오류별 해결 행동을 제공하고 펼침 집중 보기의 보이는 상태 버튼에서 서비스별 진단 화면을 열 수 있게 한다(SC-015).
- [x] 조회 제한 중 수동 새로고침 우회를 막고, 같은 결과 객체의 남은 대기 시간이 바뀌어도 화면 안내를 갱신한다(SC-012).
- [x] 화면의 짧은 상태 문구와 진단 상세를 분리하고, 원본 예외·토큰을 그대로 노출하지 않는다.

완료 조건: 동일 오류가 모든 모드에서 같은 의미로 표시되고, 사용자가 다음 행동을 알 수 있다. 대표 오류 응답을 주입한 검증과 실제 로그인 실패 사례를 기록한다. (기본 분류 구현·기존 테스트 통과, SC-012·SC-015 수정 및 사용자 동작 기준 UI 재검증 필요)

참고 파일: `providers.py`, `subscription_usage.py`, `diagnostics.py`, `ui/widget.py`, `ui/tray.py`.

## SC-002 — 마지막 정상 값과 최신 상태 구분

조회 시각 표시는 이미 일부 구현돼 있다. 오류 시각과 마지막 성공 시각을 구분하고 서비스별로 일관되게 보여 주는 데 집중한다.

- [x] 마지막 성공 결과·성공 시각과 최근 조회 시도·실패 원인을 별도로 관리한다 (`_last_successful_usage`, `last_success_at`).
- [x] 일시적 실패 시 이전 정상 값을 흐리게 유지하고 `갱신 실패 · N분 전 값`임을 표시한다 (`is_stale=True`).
- [x] 한 번도 성공하지 않은 상태는 숫자 0%로 표시하지 않는다.
- [x] 과거 값이 현재 사용량처럼 보이거나 새로운 임계치·리셋 알림을 발생시키지 않게 하고, 실패 후 같은 값으로 복구해도 임계치 알림을 중복 발생시키지 않는다(SC-013).
- [x] 재로그인·계정 변경·프로바이더 설정 변경 시 이전 계정의 값을 재사용하지 않는다 (`reset_state()`).

## SC-013 — 조회 복구 후 중복 알림 방지

## SC-016 — Antigravity의 Gemini Models·Gemini 4 Argon 한도 분리

P1 · 확인 필요 · 관련: SC-008. 2026-10-19 사용자 제보를 접수했다. 사용자가 확인한 곳은 **Antigravity 데스크톱 앱**이며 Gemini 웹·모바일 앱이 아니다.

증상: 사용자는 처음 Flash·Argon 사용량이 분리된다고 제보했고, 이어 Google AI Pro로 표시된 Antigravity 앱 사용량 화면을 제공했다. 화면에서 확인되는 실제 그룹명은 `Gemini Models`와 `Gemini 4 Argon`이다. 일반 Gemini 그룹이 Flash만의 한도라는 근거는 없으므로 임의로 `Flash`로 이름 붙이지 않는다. 현재 위젯은 CLI의 `Gemini Models` 그룹만 읽어 Argon 전용 주간 한도를 표시하지 못한다.

제공 화면의 스냅샷(현재 실시간 값이 아님):

| 화면 그룹 | 한도 항목 | 화면에 표시된 값 |
|---|---|---|
| Gemini Models | Five Hour Limit Remaining | 72% 남음, 약 33분 후 갱신 |
| Gemini Models | Weekly Limit Remaining | 65% 남음, 약 4일 22시간 후 갱신 |
| Gemini 4 Argon | Gemini 4 Argon Weekly Limit | 98%, 약 5일 7시간 후 갱신 |

Argon 항목 제목에는 `Remaining`이 명시돼 있지 않다. 화면은 별도 한도가 있음을 확인하는 근거로 사용하고, 98%가 잔여율인지 사용률인지는 실제 응답 필드로 확인한 후 변환한다. Argon의 5시간 한도는 화면에 없으므로 생성하지 않는다. `Claude and GPT models`의 5시간·주간 100%는 Gemini/Argon과 별도 그룹이며 기존 Codex·Claude 프로바이더의 계정 사용량으로 치환하지 않는다. 개인정보가 포함된 원본 화면은 저장소에 복사하지 않는다.

확인 근거:

- 현재 PC의 `agy --version`은 `1.1.12`다. 기존 조회 명령의 실제 응답에는 `Gemini Models`와 `Claude and GPT models` 두 그룹의 5시간·주간 잔여량만 있고 Flash·Argon별 행은 없다.
- 앱과 CLI가 같은 계정·플랜·한도 출처를 사용하는지는 아직 대조하지 못했다. 모델별 데이터가 CLI에 없는 원인을 CLI 버전이나 계정 차이로 단정하지 않는다.
- 합성 입력으로 `Gemini Flash`와 `Gemini Argon`의 서로 다른 5시간 한도를 주면 현재 파서는 두 항목 모두 `5시간`으로 반환한다. 그룹 식별 정보가 표시용 한도에서 사라지는 코드 문제도 확인했다. 실제 분리 응답으로 검증한 것은 아니다.
- 화면의 실제 그룹명을 사용한 별도 합성 입력에서는 `Gemini Models` 행이 있으면 `Gemini 4 Argon` 행이 그룹 필터에서 제외되는 것도 확인했다. 실제 CLI에서 Argon 행이 추가되더라도 현재 필터·파서 수정이 필요하다.

- [ ] Antigravity 데스크톱 앱·CLI의 버전, 동일 계정·플랜 여부와 사용량 화면의 정확한 그룹 이름·기간·리셋 시각을 대조한다. 계정 비밀값은 기록하지 않는다.
- [x] 제공 앱 화면에서 `Gemini Models` 5시간·주간과 `Gemini 4 Argon` 전용 주간 항목이 분리돼 있음을 확인한다. 플랜 표시는 Google AI Pro다.
- [ ] 공식 CLI의 구조화된 읽기 전용 응답 등 허용된 출처가 `Gemini 4 Argon` 한도와 수치 의미를 제공하는지 확인한다. CLI 자동 업데이트나 로그인 변경을 임의로 수행하지 않는다.
- [x] 모델/한도 그룹과 기간을 별도 식별자로 보존한다. 그룹을 버리고 `5시간`·`주간`만 남기는 변환과, 원하는 그룹이 없을 때 임의의 첫 그룹을 대신 쓰는 처리를 보완한다.

- [x] 출처가 일반 Gemini 그룹만 제공하거나 Argon 수치의 잔여/사용 의미가 불분명하면 툴팁에 `Argon 조회 미지원`을 안내한다. 수치 복제·추정이나 Argon 5시간 한도를 만들지 않는다. CLI가 반환한 풀별 행만 표시한다.
